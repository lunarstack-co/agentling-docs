Tools whose schemas come from somewhere else (an MCP server, an OpenAPI spec, a plugin) now work, and a running session can gain or lose tools.

### Added

- `AgentSession.add_tools(tools, replace=False)` and `AgentSession.remove_tools(names)` change a live session's tools. The model sees the change from its next call. Each call is all or nothing, and `final_answer` (plus `load_skill` when skills are configured) can't be removed or replaced.
- `Tool.validate_arguments` (default `True`) and the matching `@tool(validate_arguments=...)` option, for tools whose arguments are validated elsewhere.
- `Tool.validate(arguments)`, a public way to check arguments without running the tool. `call()` now goes through it.
- `examples/cli_dynamic_tools.py`, and a [Dynamic tools and MCP](/docs/guides/dynamic-tools-and-mcp) guide with an MCP bridge recipe. agentling still has no MCP dependency.

### Fixed

- A property whose `type` is a list, such as `["string", "null"]`, no longer crashes validation. A value passes if it matches any listed type, and `"null"` matches `None`.
- A schema with no `properties` no longer rejects every argument.
- Extra arguments are rejected only when `additionalProperties` is `false`.
- Validation skips keywords it doesn't implement (`anyOf`, `$ref`, `format`, nested objects) and only ever raises `ToolCallError`.

### Changed

- Tool names and schemas are checked wherever a tool is registered, not only in `@tool`. A `Tool` subclass with an invalid name or a non-object schema now fails with `ValueError` at registration.
- A `Tool` subclass whose schema doesn't set `"additionalProperties": false` now accepts extra arguments, as JSON Schema intends. `@tool` schemas still reject them.
- Loading a skill that declares a tool whose name is taken by a different tool now returns an error to the model instead of silently keeping the existing tool.
- Docstrings and the [Errors reference](/docs/reference/errors) now say which errors are reserved and not yet raised, and that provider errors reach your code unwrapped.
